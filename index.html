Tokenizer

how a language model reads text

Language models never see letters. Text is first cut into tokens, sub-word pieces with an id each, and the model only ever works with those numbers. Type below and watch it happen. Then try the Hungarian sample: every accented letter falls back to its own byte-level token, so Hungarian text costs noticeably more tokens than English.

0 tokens 0 characters 0 chars/token

A toy tokenizer that imitates GPT-style BPE, written for this site. Real vocabularies have ~100k learned merges.

From tokens to vectors

A model can’t multiply words, so every token id selects one row of an embedding matrix. From there it’s all linear algebra: dot products measure similarity and an eigen-decomposition finds the directions that matter most.

Embeddings here come from hashed character n-grams (like fastText), so tokens that are spelled alike point the same way. A trained model learns E from data, which is where meaning comes from.
